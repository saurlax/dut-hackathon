## 二、本次缺陷修复（新栈行为类 bug）

| 编号         | 现象                                                                                                                                 | 修复方案                                                                                                                                                                                                                                      | 验证                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **B1**       | 最终确认被管理员驳回后，队长仍可提交/更新作品（`saveSubmission` 只查确认"存在"不查 `auditStatus`）                                   | 要求 `teamConfirmations.auditStatus==='approved'` 才允许提交；细分文案（无确认/审核中/被驳回）；`/submission` 页面同步门控，不再给不可提交的表单                                                                                              | ✅ 集成测试四态覆盖                                    |
| **B2**       | 队长手动"暂停招募"后，编辑任一字段保存会悄悄恢复招募中（编辑分支 `recruitStatus` 重算，paused 分支因 deadline 已通过校验成为死代码） | 编辑分支保留队长意图：满员才置 `full`，否则 `existing.recruitStatus==='paused' ? 'paused' : 'recruiting'`                                                                                                                                     | ✅ 集成测试                                            |
| **B4**       | 管理员只能加不能减，无降级路径                                                                                                       | 新增 `removeAdmin` action：禁移除自己、禁移除最后一名管理员（`FOR UPDATE` 锁花名册防并发掏空）、禁移除 `ADMIN_EMAILS` 种子（登录即重提，改环境变量才能移除）；`/admin` 管理员表加两步确认"移除"按钮，自己/种子置灰                            | ✅ 集成测试（demote/self/last/missing/seed）+ 组件测试 |
| **B5**       | proxy 不在边缘拦截 `/admin`，全靠页面守卫                                                                                            | Auth.js `authorized` 回调 + `proxy.ts` 接线：未登录的 `/admin` 在边缘重定向 `/login`（防御纵深）；已登录放行给 `requireAdmin` 判角色（保持非管理员→`/?error=forbidden`）。决策抽成 `authorizeAdminPath` 纯函数                                | ✅ 单测 + build 识别 Proxy                             |
| **分页**     | 公开列表硬 `limit(100)` 无分页无提示（旧 DEF-04/17、GAP-02）；`pageSize` 负数等无钳制                                                | `publicTeams`/`publicParticipants`/`showcase` 支持 `page`/`pageSize`：`page` 钳 ≥1、`pageSize` 非正整数回退默认 12、上限 50，返回 `{items,total,page,pageSize}`；三个列表页读取参数、banner 显示真实总数、共用 `Pager` 组件（翻页保留关键词） | ✅ 集成测试（翻页/钳制/上限/去重）+ 组件测试           |
| **redirect** | Auth.js redirect 回调无单测（开放重定向风险）                                                                                        | 抽成 `resolveAppRedirect` 纯函数并单测：同源放行、相对路径钳到源、跨源拒绝、畸形回退                                                                                                                                                          | ✅ 单测                                                |

## 七、E2E 环境复现要点

1. **字体**：新 dev server 首次抓 Google Fonts 若失败会缓存 500；删掉 `.next` 重启即可（网络通时），或复用已有字体缓存。
2. **AUTH_URL**：跑 e2e 时覆盖 `AUTH_URL=http://127.0.0.1:<端口>`，否则魔法链接指向环境变量里的旧 host。
3. **Mailpit**：dev server 的 `EMAIL_SERVER_PORT` 需对齐 Mailpit 实际 SMTP 端口；E2E 设 `E2E_MAILPIT_URL` 指向其 UI 端口。
4. **测试数据库**：`TEST_DATABASE_URL` 指向独立 `dut_hackathon_test` 库（已迁移），避免污染 dev 库；`beforeEach` 会清空业务表。
